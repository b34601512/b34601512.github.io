# 官网交互演示与客户端一致性

> 首页演示必须以客户端源码和可见行为为准；只在修改演示区时读取。

### 演示区＝客户端复刻

首页演示区不是自创 UI，而是客户端主界面的复刻，配色与结构以客户端代码为准，改之前先看客户端：

- 主界面配色：取样自客户端实机截图（暖纸面 + 桃色选中 + 深墨描边），写在 `demo.css` 的 `--p-*` 变量里（`guide-film.css` 同一份）。`--w-*` 只剩聊天窗、吸附栏和话术标题红 `--w-title-fg`。
- 结构对应：标题栏（磁吸/置顶/最小化）→ 团队话术/个人话术/离线话术页签（选中页签深墨描边无底边，压在横穿整个面板的 1px `--p-base` 底线上）→ 套名说明 + 0-9 套号（未选中灰字常规字重，选中桃色块 + 深墨描边）→ 一级分类标签（同一暖灰底，选中桃色 + 深墨描边）→ 二级分类（展开的是桃色条）→ 话术行（行首 18px 奶油底小方章里一只纸飞机 + `N.` + 题红字 `--w-title-fg` + 答案）→ 一个 ⊕（主界面没有短语条）→ 搜索行（放大镜 + `Alt+Q 定位搜索栏` + 范围按钮）→ 底栏官网文案 + 小精灵；聊天窗口下方是底部吸附搜索栏。
- 一级分类不按分类上色（客户端实机也是同一暖灰底）；话术类型角标用客户端 `softtalk_knowledge_client/ui/hand_icons_pkg`（手绘风格，代码现画）导出，与客户端列表里的角标同一套笔迹（客户端已没有 `script-*.png` 图片文件）。
- 左侧聊天窗口按微信风格（`--wx-*` 变量）：灰底、白色收到的气泡、绿色 `#95ec69` 发出的气泡。
- **底部吸附搜索栏**（对应客户端 `ui/attached_search_bar_pkg`）：贴在聊天窗口底边上，宽 = 聊天窗宽。结构自上而下：结果区（向上展开、盖住聊天窗口下半截：`搜索结果 · N` + `按 Tab键，再按数字直接发送话术。` + × 关闭）→ 搜索行（输入框 + 框内 × 清除 + 范围按钮 + `›` 收起）→ 常用短语（标签 + 短语条，与主界面同一份短语）→ `最近搜索`（橙框、`清空`、chip 条）。
- 吸附栏简化（相对客户端，属有意）：客户端主界面与吸附栏的短语条都有「+」新增按钮（`LIGHT_CHIP_ADD_ACTION_TEXT = "+"`），演示是只读的所以没有；客户端主界面搜索框下面也有搜索历史面板，演示只在吸附栏里显示历史；演示的搜索历史只留最近 8 条（客户端存 50 条、显示两行）。
- 吸附栏行为：输入即搜（结果行带 1–9、0 临时序号与来源文案）、**回车发送当前选中（没选中就是第一条）**、**焦点在结果行上时按数字 1–9/0 直接发送第 N 条**（客户端 Tab 后数字直接发送）、双击/触屏点行只贴入聊天输入框、点纸飞机直接发送；**用过一条结果就收起结果并写进最近搜索**（客户端用完命中也是 `clear_query`）。搜索范围与主界面共用一份（两个范围按钮同步），搜索历史也是共用一份（最多 8 条，最近在前）。
- 折叠态：点 `›` 只剩聊天窗口右下角一个小按钮（`‹` 展开），与客户端折叠后 36×36 的形态一致。
- 演示区是假数据，但结构完整：**3 个话术域 × 0–9 十套 = 30 套**，每套自己的二级分类与话术（共 103 个二级分类、209 条话术），套号 0–9 全部可点、悬停显示套名，套号下方标题条显示「当前套名 · 第 N 套 / 共 10 套」。演示数据都写在 `demo-data.js` 的 `SCOPES` 里；首屏默认打开团队·默认套的「发货」（`DEFAULT_CATEGORY`）。
- 演示操作路径（全部可点，看到就能用）：页签切话术域、**按数字键 0–9 切套（窗口级快捷键，不用先把光标点进演示区）**、点套号整套切换、点一级分类切分类、二级分类展开收起（同一时刻只展开一个）、单击选中、**双击贴话术到输入框**、点行左侧纸飞机直接发送（粘贴 + 回车，与客户端 `list_box.py` 的 `insert_dbl`/`send` 一致）、**手机上点一下话术即贴进输入框**（触屏没有双击，否则手机用户用不了）、聊天窗口自己的发送按钮发出、常用短语直发、**搜索框回车＝直接发出当前选中（没选中就是第一条）的命中**（与客户端搜索框 Enter 一致）、命中行下面带客户端格式的来源文案。
- **数字态只被「会改变文字」的按键打断**（客户端 `_deactivate_digit_selection_for_edit_key`：`event.text()` 非空、或 Backspace/Delete）：打字、退格、删除会退出；**方向键 / Home / End 不退出**（一按方向键序号就没了是 bug）；带 Ctrl/Alt/Meta 的按键在客户端不产生文字，所以 **Ctrl+1、Alt+1 既不发送也不退出**数字态。
- **数字态下结果不够时静默**（客户端 `key_for_digit` 越界返回空、`event.accept()`）：不发送、不退出数字态。
- **`sendText` 的 520ms 定时器只清「还是这条话术」的输入框**（第 11 项抓到）：以前无条件 `clearInput()`，用户在上一条发出去后 520ms 内打的下一条会被抹掉，回车发不出去（探针在 500px 下 8 次回车只发出 5 条）。现在比对了文本才清。**写探针时手要快**（150ms 一次），不然这种竞态量不出来。
- **长探针会被节流**：页面存活久了以后 `sleep(16000)` 这类长等待会被 Chrome 拖延，探针看起来像卡死。稳妥做法是把端到端探针拆成两三个短的（每个页面只跑 15–25 秒），而不是一个跑 60 秒。上报也改成「每断言一次就 POST 一次」，卡在哪一步一眼能看见。
- **演示里的客户回复要循环用**（第 11 项抓到）：`CUSTOMER_REPLIES` 只有 6 条，以前 `CUSTOMER_REPLIES[state.replied]` 取完就没了 —— 发满 6 条之后客户永远不再回复，多玩几下像坏了。现在用 `state.replied % length` 循环，口径「每条发出去的话术都有回复」才真的成立。**数回复时注意：开场那条客户消息也是 `msg--in`**，断言要减去它。
- **核对线上要下载整站镜像到 `.live-site/`**（已进 .gitignore）：那里必须**连 assets 一起同步**，只换 index.html 会拿旧的 JS 去跑探针（第 11 项踩过：修好的循环回复没生效，白查一轮）。
- **聊天窗平台皮肤（2026 新增的演示功能）**：聊天窗上方一排标签卡（微信/京东/拼多多/千牛/抖音），点一下只改 `.chat` 的 `data-platform`，CSS 用同一组 `--wx-*` 变量换值（头像、标题栏、自己气泡、在线点、标签卡描边都跟着品牌色走），**行为完全不变**。数据来源限制：客户端源码里**没有平台白名单** —— 吸附栏认的是 `TargetWindowInfo`（前台外部窗口 + DWM 矩形 + 可见性），所以文案只能写「微信、京东、拼多多、千牛、抖音都能贴」，不能写「支持这几家」。皮肤是「一眼看出是哪家」的示意，不追求像素级复刻（抖音用深色标题栏，其余用品牌色浅底）。
- **聊天窗与话术精灵主界面必须顶底平齐**：两者都是 `.chat` / `.app`，各自 `height: 620px`（窄屏 480px）。平台标签卡要放在 `.demo` 网格的**第一行并跨两栏**（`grid-column: 1 / -1`）—— 曾经把标签卡放在聊天窗那一栏里，聊天窗被顶下去 41px，看起来就是「没对齐」。改完实测顶/底/高差都是 0px。
- **平台皮肤的真值来源＝作者提供的真实截图（PIL 取样）**。做法固定下来：把截图拷进项目 → `PIL` 取关键区域的主色（注意取**区域众数**而不是单点，单点容易采到文字/边框）→ 改成 CSS 变量 → 探针断言 `getComputedStyle` 的值**逐位等于取样值**（不是「看起来差不多」）。已核对的真值：
  - 千牛（天猫）：蓝 `#3D7FFF`（侧栏＋发送键，截图里 1197 像素完全一致）、聊天底 `#F0F2F5`、头栏白、提示条蓝 `#D8E4FF`；真实消息区是**平铺无气泡**的文字流（我们用白色气泡近似）。
  - 抖音（飞鸽）：主调是**蓝色不是粉色** —— 发送键 `#2F6DF9`、自家气泡 `#E3EFFE`、聊天底与头栏 `#F5F6FA`、买家头像青 `#35A29B`。
  - 拼多多（商家版）：聊天底白、自家气泡 `#D4E9FE`、买家头像玫红 `#F564B3`、客户端顶部标签栏紫 `#615B8A`、底栏警示黄 `#FFF3C2`；客户消息也是平铺文字（我们用浅灰 `#F2F3F5` 代表对方气泡）。
  - 京东（咚咚）：聊天底白、对方气泡 `#F7F7F7`、自家气泡 `#D9E8FF`、**发送键靛蓝 `#4960F4`**、价格红 `#F33B50`、状态标签蓝。
- **一家一个色不够用**：品牌条颜色 `--wx-strip-color`、发送键底色 `--wx-send-bg`、左侧竖条 `--wx-rail-w/--wx-rail`、头像圆角 `--wx-avatar-radius` 都拆成变量 —— 京东的发送键是靛蓝而价格是红、拼多多的紫来自客户端标签栏、千牛/抖音的蓝在左侧栏而不是顶栏，一个 `--wx-online` 撑不住。
- **断言「选中态样式」要逐张点击**：一次点击后一次性读五张卡的颜色是错的（只有最后点的那张是选中态），而且边框色有 0.16s 过渡 —— 必须「点一张 → 等过渡 → 读一张」。
- **平台皮肤的细节依据**（能核实的就核实，不能核实的别编）：品牌主色取各家官方色（京东 #E1251B、拼多多 #E02E24、千牛/阿里 #FF6A00、抖音 #FE2C55、微信 #07C160）；商家工具（京东/拼多多/千牛/抖音）标题栏加 2px 品牌条、头像圆形、发送按钮品牌色实心白字，微信桌面版没有品牌条、头像圆角方形、发送按钮是绿色。**本机代理下搜索引擎与各平台官网都拿不到真实界面截图**（Bing 图片接口返回无关结果、官方页是 JS 应用），所以皮肤是「品牌色 + 结构习惯」的示意，不是像素级复刻；要更真得由作者提供各家聊天窗截图。
- **`getComputedStyle` 返回活对象**：`const s = getComputedStyle(el)` 之后再用 `s.backgroundColor` 读到的是**读的那一刻**的值，不是取对象时的值。量「发送键亮起」这种有时限的状态时，必须当场把字符串取出来（`const bg = getComputedStyle(el).backgroundColor`），否则读的时候过渡早跑完了 —— 会得出「发送键一直是灰的」这种假结论。
- **本地性能服务的空闲退出别设太短**：探针在长循环里会静默好几秒，服务 6 秒没收到上报就自杀，之后的上报全丢，看起来像「探针卡住了」。
- **窄屏布局要分开断言**：≤900px 演示区是竖排，聊天窗在话术精灵主界面**上方**，硬套宽屏的「顶底差为 0」必然假红。
- **量过渡属性的坑**：`.chat-send` 有 0.18s 过渡，输入后立刻 `getComputedStyle` 会量到中间色（京东量成 rgb(228,67,59)）。要么等 400ms 再量，要么在注入页里禁过渡。
- **静态预渲染要和 JS 初始态对齐**：未选中的 4 个标签卡在静态 HTML 里就带 `tabindex="-1"`（roving tabindex），JS 起来后 `setChatPlatform` 再对一次，避免闪烁与两份状态。
- **截图别用 `--virtual-time-budget` 看过渡**：虚拟时钟下 CSS 过渡不推进，截图会停在过渡起点 —— 明明标签已切到京东，图里高亮还在微信（状态其实是对的，数值探针可证）。截图验证要么在注入页里禁过渡，要么不用虚拟时钟。
- **探针报「溢出 165px」先查探针自己**：`--window-size=1280,000` 这种笔误会让页面没正常布局，量出来的越界全是假的。
- **性能要用真实时间量，别用 `--virtual-time-budget`**：虚拟时钟会把所有耗时压成 0.0ms（曾经量出「40 次切套 0.1ms」这种假数据）。可靠办法：`node .perf-serve.mjs` 起本地静态服务 + 页面探针把报告 POST 回 `/__report`（`.perf*.mjs/js` 已进 .gitignore）。**每一项耗时都必须带「真的生效」断言**，否则测到的是空转（另一次教训：探针在循环外抓了一次节点，重绘后节点失效，点击全落空，同样量出 0.00ms）。
- **第 10 项量到的真实数据**（本地服务、真实时间、全部带生效断言）：FCP ≈250–280ms、DCL ≈250ms；整棵树重绘（切套）1.7ms、搜索输入 0.35ms、展开收起 0.12ms、聊天框输入 0.27ms、数字键发送 6.3ms、滚动 0.01ms；DOM ≈200–270 节点；长任务 0–1 个（77–90ms，出现在加载那一下，机器负载影响大）；线上 gzip 后总传输 ≈35KB（HTML 4.8KB + JS 23.5KB + CSS 7.2KB + 图标 ≈4KB）。两个演示脚本改成 `defer`（内容是静态预渲染的，首屏不必等 87KB JS 解析执行）。
- **构建脚本的确定性**（第 9 项审出来的）：sitemap 的 lastmod **不能写死构建当天**（以前是 `new Date()`，每次构建都假装四个页面刚更新，搜索引擎会当噪声）——现在的规则是「内容相对 `git show HEAD:<页面>` 真的变了才写今天，否则沿用它上次发布的日期」；资源指纹 `?v=` **按 LF 归一后再算**（仓库存 LF、本地检出 CRLF，不归一的话换台机器重新构建会把四个指纹全换一遍）。**验构建是否干净的办法：提交后跑一次 `node scripts/build-site.mjs`，`git status` 必须还是干净的**。
- **文案对着客户端源码核，别凭印象**（几个已经核过的事实）：行的左侧图标在客户端是**纸飞机**（`list_box_helpers_mixin._draw_send_icon` 画的是指向左边的纸飞机，代码注释叫「左侧箭头」），所以文案统一说「点左侧纸飞机」；自动备份的触发是**保存时 / 删除前**（`auto_backup` 设置页标签「保存时自动备份」「删除前自动备份」），不是「按天」；搜索范围「当前」＝**当前话术域 + 当前套号**（`search_range_engine.resolve_effective_search_targets`）；客户端原文：吸附栏两点是「常用短语：」与「最近搜索」，结果标题是「搜索结果 · N」，空结果是「没有匹配结果」，导入支持「Excel（.xlsx）与完整恢复包（.stpkg）」，云端角色是超级管理员 / 只读工号，工号权限分「团队话术」「个人话术」两栏。**JSON-LD 里不要写页面上没有、或不打算做的东西**（曾经写进 Alt+W/Alt+R 而演示只做 Alt+Q）。
- **用完搜索命中就退出搜索并定位那条话术**（客户端 `complete_external_insert_search_use`：记搜索历史 → `_leave_search_context` 清空搜索词退出搜索态 → `locate_faos_in_main_by_ids`；吸附栏是 `bar.clear_query()` + 同样定位）。演示里**四件事都算「用了命中」**：数字键发送、回车发送、纸飞机直发、双击/触屏单击/回车空格贴入。做法是 `usePanelHit` / `useBarHit` → `locateHit`：切到命中所在话术域、套号、一级分类，只展开命中所在那一节，再选中那一行。**不要在搜索态里发完还留在结果列表**（那是我们早期做错的地方）。
- **探针发键盘事件要发在「聚焦的元素」上**：真实浏览器把 keydown 派给聚焦元素，`document.body.dispatchEvent` 会让 `closest(".attached")` 判断出一个假 surface（曾因此让吸附栏那组断言全红，白查一轮）。另外数字选择态下数字是**搜索框自己的 keydown 处理**在管（客户端也是输入框过滤器接管），所以光标留在搜索框里按数字必须能发。
- **键盘可达性**：二级分类标题是 `role="button"` + `tabindex="0"` + `aria-expanded`，回车/空格都能展开收起；话术行（`role="button"`）回车和空格都＝贴进输入框；范围按钮用**真 `<button>`**（曾经是 `span role=button`，键盘按了没反应）；三个输入框都带 `aria-label`；页签/套号/一级分类用 `aria-pressed` 报选中态；纸飞机等纯图标按钮带 `aria-label`。**给 role=button 的元素加键盘响应**这条要记住：native button 才会自动响应回车/空格。
- **吸附栏输入框的焦点指示给外层 `.attached-row:focus-within`**：输入框自己是 `border:none` + `outline:none`，光靠它键盘用户看不出焦点在哪。
- **两个低于 4.5 的对比度是客户端自己的配色，按原样复刻**：话术行标题 `#E53935`（客户端 `faq_title_colors.DEFAULT_FAQ_TITLE_FG`，3.57）、吸附栏提示语 `#7A8695`（客户端主题 `muted_text`，3.70）。演示区其余文字都 ≥ 4.5。
- **用 Python 改写仓库里的文件时不要自己拼 `"
  "`**：`pathlib.write_text` 默认会把 `
  ` 按平台再翻一遍，在 Windows 上得到 `

`（demo-data.js 曾因此每行多一个空行、体积多 4KB 还上线了）。要写 CRLF 就 `open(..., newline="")`，否则一律写 `
` 让 git 处理。

- **气泡必须 `white-space: pre-wrap`**：Shift+Enter 打出的换行（以及话术里自带的多行）发出去以后还要是换行，否则 HTML 会把换行折成空格。
- **客户回复是排队的一条一条**：每条发出去的话术对应一条回复（`state.replyQueue` + `drainReplies`），有打字动画、不并发；之前只有第一条能收到回复。
- **「最近搜索」的显示规则照客户端 `search_history.build_search_history_visibility_plan`**：有历史 **且** 输入框为空 **且** 面板激活（焦点在吸附栏里，客户端是输入框 FocusIn/FocusOut 控制 `panel_active`）三者同时成立才显示；焦点离开吸附栏就收起来。词条显示超过 **12 字**截断加省略号（`build_search_history_bar_payload`），点下去仍用完整关键词。
- **搜索历史只在「用过某条命中」时记录**（客户端 `build_search_hit_use_plan`：insert/insert_dbl/send）：搜了但没用的关键词不进历史，所以「搜一个没有结果的长词再回车」不会写历史。
- **吸附栏几何照客户端 `widget_positioning_mixin`**：展开宽＝外部聊天窗宽（客户端 `max(220, window_right - window_left)`）、左边缘对齐聊天窗左边缘、折叠态是 **36×36** 的右下角小按钮（`x0 = window_right - 36`）。
- **收起吸附栏会清空搜索**（客户端 `set_collapsed` → `clear_query`），顺带退出数字态，不会留下隐藏的带序号结果行。
- **Tab 数字选择态**（对应客户端 `search_result_digit_selection`，主搜索框与吸附栏共用同一套）：两个搜索框里输入关键词后按 **Tab**，前十条结果的临时序号（1–9、0）才会出现，再按数字＝**直接发送**第 N 条；继续打字/退格退出数字态，Esc 先退数字态、再按一次才是清空搜索。序号只在数字态显示（客户端 Tab 前也不显示）。
- **二级分类同一时刻只展开一个**（客户端 `expanded_level2_key` 是单个键）：点已展开的标题＝全收起，点其他标题＝只留这一个并收起上一个；切套/切话术域/切一级分类都回到「第一节展开」（客户端 `_resolve_level2_selection` 在目标键不存在时回落到首个）。演示里这个状态存在 `SCOPES` 的 `section.open` 上，靠 `resetSections()` 统一重置，别在别处再写一遍。
- **点列表空白处清除选中**（客户端 `PaintedListBox.mousePressEvent` 里 `clear_selection`）。
- **列表重建要把焦点还回去**：切套/切分类/数字发送都会重画话术列表，重建前记住「焦点在第几行」，重建后 `focus({preventScroll:true})` 还回同一位置；否则第二次按数字切套就没有目标（焦点掉到 body），表现为「只有第一次有效」。
- **「滚过去」看的是话术面板（`.app`）而不是整个演示区**：窄屏（≤900px）时演示区上下堆叠、比屏幕还高，用整个演示区判断会导致每按一次数字/Alt+Q 都滚一次屏；面板已经在视野里就绝不滚动。
- **数字键是窗口级快捷键，不要求先把光标点进演示区**（客户端用 `QKeySequence` + `Qt.WindowShortcut`）：刚打开页面、什么都没点时按数字也要切套；唯一让位条件是「正在打字」（`INPUT`/`TEXTAREA`/`contenteditable`）。别写成「必须先点演示区」，否则访客不点就没反应。演示不在视野时先 `scrollIntoView` 再切，让人看得见反应。
- **数字键顶部与小键盘都要认**（客户端 `QKeySequence("0".."9")` 两种键盘都匹配）：切套与数字发送都走同一个 `readDigit()`，别只判 `event.code === "DigitN"`，否则小键盘无效。
- **主搜索框提示语跟着焦点换**（客户端 `shortcut_discoverability`）：未聚焦 `Alt+Q 定位搜索栏`（idle），聚焦后 `按 Tab键，再按数字直接发送话术。`。
- **右下角范围按钮只有「全部 / 当前」两种**（客户端 `search_range_engine` 是 `all / current / custom`，标签 `全部 / 当前 / 自定义`）：`all` ＝三类话术全部 0–9 套，`current` ＝当前话术域 + 当前套号。演示不做「自定义」那个勾选弹窗，所以**不要造客户端没有的中间态**（曾经写过「当前话术域」，是错的）。主界面与吸附栏两个按钮共用同一份状态。
- **命中来源文案照抄客户端**（`search_result_source.py`）：`团队·默认｜售前 > 价格问题`（话术域·套号｜一级 > 二级，0 号套写「默认」，1–9 写「第N套」）。客户端把这段放在悬停预览气泡里，演示没有气泡，就直接跟在话术行下面。
- **搜索无结果文案＝客户端原文「没有匹配结果」**（`search_result_sections.py` 自动排序卡片的 `empty_text`）。
- **搜索框回车＝发送当前选中的那条命中**，没有选中才发第一条（客户端 `_handle_enter_key` 的 `current_key` 规则）；主界面回车也记一条搜索历史。**用户用了某条命中就会写进「最近搜索」**，两个搜索面共用一份。
- **Esc 退出搜索后不再停在输入框**（客户端 `_handle_escape_key` / `_exit_search_and_restore_focus`）：主界面把焦点交给话术列表**第一行**，二级分类全收起、列表里没有行时交给**列表控件本身**（`#demo-list` 带 `tabindex="-1"` 才能被脚本聚焦，客户端也是把焦点给列表控件），吸附栏把焦点还给聊天输入框；搜索框本来就是空的时按 Esc 不动作。
- **Alt+Q 定位搜索框**（任何位置按都生效，带一次橙色短高亮），行 `title` 提示「双击贴进输入框，点左侧纸飞机直接发送」。
- **带图片 / 附件的话术**（对应客户端 answer-v3 有序正文，`phrase_sequence.py`）：数据写在话术上的 `images`（第 1 段文字后的图片名）、`more`（后续各段）、`files`（普通附件 `{name,size}`），**类型角标和列表预览都由内容推出来**（`typeTag` / `previewText`，预览照 `derive_preview` 写成 `[图片]`、`[文件]名称`），别再手写 `tag`。双击＝整条内容进输入框（文字进 textarea，图片与附件显示在输入框上方的 `#demo-input-media` 条里，可点 × 移除），按回车或发送键一起发出；纸飞机＝按 `build_execution_plan` 逐段发出（每段「文字 + 段内图片」，间隔 500ms），普通附件最后一次投递，整条发完才计 1 条、排 1 条客户回复。示例是团队·默认套「售前 > 欢迎话术」里的「店铺介绍」（首屏不再直接显示它，首屏是「发货」），别删。
- 客户自动回复、重置按钮照旧。凡是新加交互，优先做成"点一下就有反应"，不要加说明文字。
- 聊天输入框是真实的 `<textarea id="demo-input">`（不是假 div）：双击话术是填入而不是锁定，访客可以直接改字、自己打字；**回车发送（微信习惯）**、Shift+Enter 换行（要加 `isComposing`/`keyCode 229` 判断，否则中文输入法选词的回车会误发），多行时自动长高（上限取 CSS `max-height`，默认 70→140px 后内部滚动）。改样式时别把它写回固定高度或去掉 `resize: none`。
